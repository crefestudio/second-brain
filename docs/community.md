# 노셔너블 클럽

## 2026-11-11 클럽·1:1 채팅 변경

- 글 본문은 Tiptap StarterKit으로 작성한다. 제목·굵게·기울임·목록·인용·링크·코드·구분선과 입력 중 마크다운 단축 문법을 지원한다. 마크다운 원문 가져오기/내보내기는 포함하지 않는다. 기존 `body`는 목록·알림·외부 공유용 평문으로 유지하고, `bodyDocument`에는 서버가 검증한 제한된 JSON 문서를 저장한다. 기존 평문 글은 그대로 읽고 편집할 수 있다.
- 새 글은 임시저장할 수 있다. `communityMemberPrivate/{uid}/drafts/{id}`에 서버 전용으로 저장하며, 관리자 포함 다른 계정의 임시저장 API 조회를 허용하지 않는다. 내 글 → 임시저장 목록, 실제 글 형태의 미리보기, 이어 쓰기, 삭제를 제공한다. 불완전한 제목·본문도 저장할 수 있으며 revision 검사로 여러 창의 덮어쓰기를 방지한다.
- 게시하기는 같은 ID의 게시글 생성과 임시저장 삭제를 한 트랜잭션으로 처리한다. 작성 시각은 게시 시각이며, 기존 공개 범위·권한·알림 규칙을 그때 적용한다. 임시저장에는 알림 이벤트를 생성하지 않는다. 이미 게시된 글의 수정본 임시저장과 자동저장은 이번 범위에 포함하지 않는다.

- 고정은 관리자만 설정한다. `pinExpiresAt`이 현재 시각보다 큰 공개 글을 해당 방의 위쪽과 오른쪽 ‘고정된 글’에 표시한다. 방 목록의 일반 글에서는 중복을 제외하고 형식 필터를 적용한다. 전체 글은 본문 최신순을 유지하며 오른쪽에는 모든 방의 고정 글, 그 아래에는 공개 글 중 공감 수 상위 5개를 표시한다. 공감 0개·비공개·삭제·숨긴 방·탈퇴한 작성자의 글은 인기 목록에서 제외한다. 내 글 오른쪽에는 모든 방의 고정 글을 표시한다. 모바일에서는 오른쪽 영역을 목록 위로 옮긴다. 항상 고정은 `Number.MAX_SAFE_INTEGER`, 하루 고정은 설정 시각+24시간, 해제는 0이며 만료는 조회 시 즉시 반영한다.
- 게시글의 방 이름 배지는 날짜 오른쪽에 표시하고 클릭 시 해당 방으로 이동한다. 해당 방 안에서 보는 글과 현재 고정된 글에는 배지를 표시하지 않는다. 오른쪽 목록은 박스 밖 제목과 박스 안 프로필 이미지·글 제목만으로 구성하며 설명 문구는 없다. 첫 박스는 작성 박스 상단에 맞춰 정렬하고 환영 안내와 상태 알림은 월페이퍼 너비에 맞춘다.
- 알림 설정은 내 활동 → 관리자 새 글 → 중요 기본 공지 → 이벤트 순서다. 알림함은 고정 높이 안에서 스크롤하고, 로딩·빈 목록·많은 알림 간 전환 시 창 크기를 유지한다.

- 알림 수신은 `adminPosts`(일반 관리자 새 글), `activity`(댓글·답변·채택·운영 안내), `notices`(공지사항 방 관리자 글), `events`(이벤트 방 관리자 글)의 메일·톡 8개 선택으로 저장한다. 가입과 설정 화면에서 같은 표를 사용한다. 기존 채널별 설정은 각 항목에 그대로 상속한다.
- 알림함은 수신 선택과 무관하게 유지한다. 공감·1:1 채팅은 클럽 내부 알림만 사용한다. 발송 시 해당 분류를 확인하며, 대기 메일에도 분류를 저장해 실제 발송 직전 수신 설정을 재검사한다. 분류가 없는 과거 대기 메일은 모든 메일 항목이 허용된 경우에만 발송한다.

- 운영 주소: `https://club.notionable.net/`. 이전 `/community` 경로는 호환용으로 유지한다.
- 상단 Notionable 로고 옆에 ‘클럽’을 표시한다. 요청하기 방은 숨겨 기존 데이터를 보존하고, 주제방의 위젯·가계부를 복원한다.
- 요청 형식은 라이프업·비즈업·주제방 하위 방에서만 새로 작성할 수 있다. 서버에서도 같은 제한을 적용한다.
- 상단 채팅 버튼과 멤버 카드에서 1:1 대화를 시작한다. 전체 채팅방·그룹 채팅·첨부파일·외부 푸시 알림은 이번 범위에 포함하지 않는다.
- 알림 수신 설정의 `다른 멤버의 DM 허용`은 기본 해제이며, 개인 설정 `allowMemberDm === true`일 때만 일반 멤버의 메시지를 받는다. 대화 시작과 매 전송에서 서버가 재검사한다. 관리자와의 양방향 DM은 이 옵션과 무관하게 허용하지만 개별 대화 차단은 유지한다. 첫 DM도 이메일로 발송하지 않는다.
- 메시지는 `communityChats/{chatId}/messages`, 개인 대화 목록은 `communityMemberPrivate/{uid}/chats`에 저장한다. 내용을 조회하거나 변경하는 모든 작업은 `communityApi`에서 활성 멤버·대화 참여자 여부를 검사한다. 관리자의 타인 대화 조회 권한은 없다.
- `communityChatSignals/{uid}`는 본인에게만 읽기를 허용하고 변경 시각·리비전만 담는다. 클라이언트가 이 문서를 실시간 구독해 API로 내용을 새로 불러온다. 모든 클라이언트 쓰기와 메시지 직접 읽기는 금지한다.
- 메시지 40개·대화 목록 30개 단위로 이전 항목을 불러온다. 전송 재시도는 메시지 ID로 중복을 방지하고, 서버에서 사용자별 1초 전송 간격과 4,000자 한도를 검사한다.
- 본인 메시지 삭제, 상대 차단·해제, 읽지 않음 표시를 지원한다. 탈퇴하거나 비활성화된 멤버와의 대화는 조회·전송을 차단한다. 삭제된 메시지는 본문을 비우고 삭제 표시를 남긴다.
- 로컬 검증: `community-chat.test.cjs`, `community-chat-rules.test.cjs`, `test-club-chat-ui.cjs`. UI 테스트는 로컬 Firestore에서 두 멤버의 실제 Angular 화면·API·실시간 구독을 연결한다. 운영 계정에 시험 메시지를 전송하지 않는다.

## 구성

- 기존 Angular 앱의 `/community` 경로를 사용한다.
- `community.notionable.net`의 루트(`/`)는 `/community`로 이동한다. 기존 앱 호스트의 루트 동작은 유지한다.
- Firebase 프로젝트와 Hosting 사이트는 기존 `notionable-secondbrain`을 사용한다. 이 구현에는 별도의 Hosting 사이트가 필요하지 않다.
- 기존 Google 로그인 또는 라이프업 구매 이메일 로그인을 재사용한다. 커뮤니티 가입은 별도 확인을 받아 저장하며 상품 구매·회원 등급과 무관하다.
- 같은 Firebase UID를 사용하지만 브라우저 로그인 저장소는 도메인마다 다르다. 앱에서 로그인했다고 커뮤니티 도메인까지 자동 로그인되는 SSO는 포함하지 않는다. 커뮤니티 첫 방문에는 같은 계정으로 로그인한다.

## 공간과 동작

| 묶음 | 방 |
| --- | --- |
| 시작하기 | 커뮤니티 소개, 공지사항, 이벤트, 요청하기 (이야기 전용) |
| 함께 나누기 | 인사하기·알림 마당 (이야기), 묻고 답하기 (질문 답변) |
| 공부하기 | 노션, GTD, 세컨드브레인, AI / 자동화 (둘 다) |
| 주제방 | 카카오톡 비서, 루틴 관리, 커뮤니티, 위젯, 가계부 (둘 다) |
| 서비스 | 라이프업, 비즈업 (둘 다) |

커뮤니티는 멤버 전용으로 유지한다. 검색 공개/SEO 확장은 보류하며, 추후 운영자가 직접 쓴 글 중 공개할 글만 홈페이지에 별도로 발행하는 방향으로 검토한다. 현재 자동 발행이나 기존 글의 공개 전환은 구현하지 않는다.

기본 목록은 제공된 노션 문서에 맞췄다. 방 정의는 `functions/src/community-model.ts`에서 서버와 화면이 공유한다.

- 가입한 멤버만 글, 답글, 멤버 목록을 조회하고 작성할 수 있다.
- 전체 글에는 인사하기·질문을 포함한 모든 방의 글이 최신순으로 나타난다. 방과 일반 피드/질문 답변 필터를 함께 사용할 수 있다.
- 전체 글 아래의 내 글(`?view=mine`)은 로그인한 사용자가 작성한 글만 최신순으로 보여준다. 형식 필터·더 보기·상세에서 목록으로 돌아오기를 지원한다.
- 글 작성 시 비공개를 선택하면 작성자와 관리자만 목록·상세·댓글에 접근할 수 있다. 다른 회원의 읽지 않은 글 수에도 포함하지 않는다. 공개 범위는 게시 후 변경할 수 없으며 기존 글은 공개 글로 취급한다.
- 비공개 새 글은 관리자에게만 개별 알림을 생성하며 뉴스레터·카카오 전체 공유·인스타그램 공유를 허용하지 않는다. 댓글·답변 채택 알림은 기존처럼 해당 작성자에게 전달한다.
- 내 글 조회용 `authorId` 복합 인덱스 4개가 추가되었다. 운영 반영 시 인덱스 준비 완료 후 서버와 화면을 함께 배포해야 한다.
- 2026-11-09 운영 반영 완료: 인덱스 4개 READY, `communityApi`와 알림 함수 3개 ACTIVE, Hosting 배포 완료. 운영 `/community` HTTP 200과 로컬 빌드/운영 커뮤니티 번들 일치를 확인했고, 미인증 API는 401로 차단됨을 확인했다. 비공개 글은 목록·상세에서 자물쇠와 함께 표시된다. 인덱스의 기본 문서 ID 정렬(`__name__`)은 CLI가 자동 처리하도록 명시 항목을 제거했다.
- 방의 kind 설정은 feed(이야기), question(질문 답변), both(둘 다)이다. 단일 형식 방은 편집기 형식 선택을 잠그고 서버에서도 해당 형식을 적용한다. 관리자에게도 동일하다. both 방과 전체 글에만 전체/이야기/질문 답변 필터를 표시한다.
- 활용 가이드는 폐쇄해 피드와 상세 조회에서 제외하고 원본 데이터는 보존한다. 기존 development ID는 주제방 섹션의 커뮤니티 방으로 유지한다.
- 질문 작성자만 답변을 채택·취소할 수 있다. 채택 답변을 수정하거나 삭제하면 채택 상태가 해제된다.
- 글·답글은 작성자 또는 기존 앱 운영자가 수정·삭제할 수 있다. 소개·공지·이벤트 방은 운영자만 글을 작성한다. 운영자 판정은 서버의 기존 `ADMIN_EMAILS`를 사용하며 회원 등급은 만들지 않았다.
- 멤버 프로필에는 이름·프로필 사진·한 줄 소개·가입일을 공개한다. 이메일은 공개하지 않는다. 기존 글에는 작성 당시 이름이 남는다.
- 프로필 편집에서 JPG·PNG·WebP(최대 5MB) 사진을 선택·미리보기·삭제할 수 있다. 저장 전에는 변경되지 않으며 취소하면 원래 사진을 유지한다. 사진이 없거나 로딩에 실패하면 이름 첫 글자를 표시한다.
- 브라우저와 서버가 사진을 192px 정사각형 JPEG로 정규화한다. 서버는 실제 이미지 디코딩·크기 검증 및 메타데이터 제거 후 최대 48KB 썸네일만 `communityMembers.avatar`에 저장한다. 원본 파일이나 외부 공개 URL은 저장하지 않는다.
- 계정·글쓰기·글·댓글·채택 답변·멤버 목록에서 사진을 표시한다. 글/댓글 조회 시 작성자의 현재 사진을 중복 없이 조회하므로 기존 게시물에도 사진 변경·삭제가 반영된다. 사진은 기존 멤버 전용 API를 통해서만 전달한다.
- 사진 검증: `community-avatar.test.cjs`에서 파일 디코딩·정규화·권한·이전 글/댓글 반영·삭제를 확인했고 UI 테스트에서 미리보기·취소·저장·새로고침·삭제 및 모바일 레이아웃을 확인했다. 빌드와 lint 통과(기존 경고 있음). 기존 동시 글 생성 테스트는 Firestore 에뮬레이터 1.19.8에서 `Transaction is invalid or closed`로 실패하며 변경 전 HEAD 코드에서도 같은 오류가 재현됐다.
- 2026-11-09 프로필 사진 운영 배포 완료: `communityApi` ACTIVE, Hosting 배포 및 운영 번들 일치 확인. 미인증 프로필 변경 요청은 401로 거절됨을 확인했다. 운영 회원의 실제 사진을 변경하는 테스트는 수행하지 않았다.
- 상단 알림에서 개인 알림함을 조회한다. 채팅은 아직 비활성 메뉴다.
- 본문은 일반 텍스트다. 이미지·파일 첨부, 리치 텍스트 편집, 검색, 신고·차단 관리 UI는 이번 구현에 포함하지 않았다.

## 저장과 접근 제어

`communityMembers`, `communityPosts/{postId}/comments`, `communityPosts/{postId}/likes`, `communityMemberPrivate`를 사용한다. 모든 접근은 `communityApi`를 거치며 기존 Firestore 규칙의 기본 거부로 브라우저 직접 접근은 차단된다.

서버는 Firebase ID 토큰과 취소 여부, 인증된 이메일, 계정 삭제 대기 상태, 커뮤니티 멤버 여부, 작성자·운영자 권한을 검사한다. 응답은 `private, no-store`이며 서비스 워커에 커뮤니티 API 응답을 저장하지 않는다.

쓰기에는 트랜잭션을 사용한다. 글·답글의 클라이언트 생성 ID는 응답 실패 후 재시도에도 유지되어 동일 요청이 중복 생성되지 않는다. 버전으로 오래된 수정·삭제 요청을 거부한다. 새 글은 10초, 새 답글은 2초 간격을 둔다. 공감은 사용자당 한 건이며 원하는 상태를 보내는 방식으로 재시도에 안전하다.

삭제한 글은 제목·본문을 비우고 비공개 처리한다. 그 글과 답글은 API에서 더 이상 조회할 수 없다. 삭제한 답글은 내용을 비우고 삭제 표시를 남긴다. 원문 이력이나 복구 기능은 제공하지 않는다. 하위 레코드와 작성자 ID는 보존되므로 별도의 개인정보 삭제·보존 정책이 필요할 경우 후속 정리 작업을 추가한다.

### 카카오 챗봇 Event API 설정 안내

1. 기존 봇에 비즈니스 인증 채널·비즈앱·월렛을 연결한다. 수신자는 채널을 친구 추가해야 한다.
2. 별도 알림 블록에 이벤트 이름 community_notification을 등록한다. 필수 파라미터는 두지 않는다. 기존 카카오 수집 스킬을 호출하지 않는 독립 블록으로 구성한다. 텍스트 말풍선:

    {{#current.event.data.text}}
    {{#current.event.data.url}}

3. 챗봇 변경을 배포하고 REST API 키를 Firebase Secret Manager에 등록한다. 키를 소스나 채팅에 저장하지 않는다.

    firebase functions:secrets:set COMMUNITY_KAKAO_REST_API_KEY --project notionable-secondbrain

4. functions/.env.notionable-secondbrain의 공개 설정:

    COMMUNITY_KAKAO_ENABLED=true
    COMMUNITY_KAKAO_BOT_ID=실제_봇_ID
    COMMUNITY_KAKAO_EVENT_NAME=community_notification

5. communityApi, deliverCommunityNotification, processCommunityNotificationDelivery를 재배포한다. 수신 시험 계정에서 먼저 검증한다. 미설정/false 상태에서는 카카오 API를 호출하지 않는다.
6. 수신자는 라이프봇 앱에서 기존 카카오 연결을 완료하고 채널에 메시지를 한 번 보낸다. 현재 소유 워크스페이스와 양방향 연결, 최근 캡처 기록의 명시적 사용자 키 타입을 확인한다. 연결이나 키 타입을 확인할 수 없으면 발송하지 않는다.
7. SUCCESS는 요청 접수다. taskId로 결과를 조회해 실제 성공을 확인한다. POST 응답이 끊기거나 작업이 중단돼 결과가 불명확하면 review로 보류하고 자동 재전송하지 않는다. 성공 메시지는 건당 과금되므로 월렛·사용량을 확인한다.

## 뉴스레터 알림과 발송 이력 (2026-11-11)

- 수동 뉴스레터는 이메일 전용이며 클럽 알림함에 중복 노출하거나 읽지 않은 수를 증가시키지 않습니다. 기존 수동 뉴스레터 알림은 사용자별 최초 상태/알림 조회에서 숨기고 읽지 않은 수를 보정합니다. 메일 처리 기록은 유지합니다.
- 본문 옆 메일 발송 건수 배지는 제거하고 수정 → 발행에 누적 발송 처리 건수와 최근 요청 시각을 표시합니다. 이는 고유 수신자 수나 받은편지함 도착 보장이 아닙니다.
- 버튼은 뉴스레터 미리보기로 변경합니다. 최종 발송 확정은 기존처럼 별도 버튼으로 수행합니다.
- 댓글 영역 제목은 댓글/답변으로 표시하고 빈 댓글 권유 문구는 제거합니다.
- 중복 수신자 제외 검토: communityMailQueue에는 communityNewsletterPostId, recipient, status, sentAt가 남습니다. 글 ID + 정규화 이메일 기준으로 sent/pending/sending/review를 제외하는 것이 적절합니다. 실패·취소 건 재시도 정책과 동시 요청 방지, 기존 기록 이관까지 별도 구현이 필요합니다. 이번 변경에서는 재발송 정책을 변경하지 않았습니다.
- 블로그는 보류 상태입니다. publishWebsite/unpublishWebsite API는 503을 반환하며 공개 페이지/주소를 배포하지 않습니다.
